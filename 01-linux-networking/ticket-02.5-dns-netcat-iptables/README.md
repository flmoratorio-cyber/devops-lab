# Ticket 02.5 — Local DNS, netcat and iptables chains

🇬🇧 English · [🇦🇷 Español](README.es.md)

## Objective
Reach nodes by name, test real TCP ports (not just ICMP) and understand the iptables chains that Docker and Kubernetes rely on.

## 1. Local name resolution (`/etc/hosts`)

```bash
echo "192.168.124.101 wk1" | sudo tee -a /etc/hosts > /dev/null
```

**Why `sudo echo "..." >> /etc/hosts` fails:** the redirection (`>>`) is performed by *your* shell as your user, not by `sudo`. With `tee -a`, the write is done by a process that runs as root (`-a` = append; `> /dev/null` hides tee's echo).

Remote, without logging in (single quotes so the pipe runs on the node, `-t` for the sudo prompt):

```bash
ssh -t wk1 'echo "192.168.124.10 master" | sudo tee -a /etc/hosts'
```

## 2. Two SSH errors worth reading carefully

**`WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!`** — the host key stored in `known_hosts` no longer matches the node (cloned VMs / reused IPs). Verify it is expected, then remove the stale entry:

```bash
ssh-keygen -f ~/.ssh/known_hosts -R 192.168.124.101
```

**`Permission denied (publickey)` when using the hostname** — the `Host 192.168.124.*` block in `~/.ssh/config` only matched IPs. Fix by matching names too:

```text
Host 192.168.124.* wk*
    IdentityFile ~/.ssh/lab_master
    User <user>
```

## 3. Layer 4 checks with netcat

`ping` only proves ICMP (L3). A firewall can pass ping and block the service.

```bash
nc -zv wk1 22        # -z: scan only, no data   -v: verbose result
```

## 4. iptables chains

```bash
sudo iptables -L -n -v      # -n numeric, -v counters and interfaces
```

| Chain | Traffic | Example |
|-------|---------|---------|
| `INPUT` | Packets destined **to this node** | someone SSHes into the node |
| `OUTPUT` | Packets **generated by this node** | the node pings another host |
| `FORWARD` | Packets that **pass through** the node (it acts as a router) | container/pod traffic leaving the host |

An empty table with `ACCEPT` policies is normal on a fresh Ubuntu. `FORWARD` is why Kubernetes needs `net.ipv4.ip_forward=1` (see ticket 11).
